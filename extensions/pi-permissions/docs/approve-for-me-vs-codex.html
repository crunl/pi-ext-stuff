Approve for me · Pi vs Codex

对照 Codex main 7625bd56（2026-08-26）与本扩展当前 auto 链路。 产品意图相同：该问的时候让 Guardian 代批，失败闭合，不弹给人。 运行时已经不是同一条路。

Codex Pi Guardian 人审 / 分叉 sandbox 对齐 / 放行 拒绝

① 产品开关不是同一维

Codex 把「何时问」和「谁来批」拆开。TUI 里同一个 workspace-write + OnRequest preset，换 reviewer 就从 Default 变成 Approve for me。 Pi 把两轴压成 auto / yolo，人审 popup 已退休。

② 决策与执行边界

Codex 审批嵌在 orchestrator：先政策、再（可能）Guardian、再第一次进沙箱。 Pi 由一个 Engine 贯穿 admission、Guardian 和 capability lease；宿主只在 tool_call 处理 generic host-admission，managed tools 在 execute 直接进入同一决策核心并由拥有边界的 adapter 执行。

④ 会分叉的点

已对齐request_permissions 谁批
Codex AutoReview
直接 Guardian。Approved → turn，ApprovedForSession → session。Deny / timeout → 空权限。User reviewer 才弹人。
Pi auto
Engine 以 permission-amendment ownership 送 Guardian；只有批准且 acknowledgement 成功后才写入 turn/session capability world。
分叉审之前谁拦
Codex
exec_policy Allow / Prompt / Forbidden。普通 workspace 命令 Allow，沙箱自己挡。private 走代理 NotAllowedLocal，不审。
Pi
classifyRisk LOW / REVIEW / HARD。private IP、畸形 git、protected config HARD block，Guardian 看不到。
P1Guardian 能干什么
Codex child
整颗只读 profile 的 Codex 会话，标准 runtime 含 shell。清空 MCP / Apps / Hooks / WebSearch。
Pi
暴露 read / grep / find / ls / inspect。inspect 使用固定 {command:string} schema，参数和输出有上限；外层固定 /bin/bash -c，经 Nono 只读/无网络 profile 与 30s host deadline 约束，临时 scratch 遵循 sandbox 默认值。
P1沙箱失败后的「升级」
Codex
require_escalated 可 bypass 首跳。OnRequest 沙箱拒绝后默认 不 unsandbox 重试；网络拦截例外再审。
Pi
没有 unsandbox 重试。精确 filesystem capability 由 Engine 形成 lease，Nono profile 仍是最终 enforcement owner；只有 cwd `.git` 的 grantable deny 可被 exact grant 移除。
P1网络默认语义
Codex
独立 NetworkAccess 审批 + managed proxy。审的是一次 CONNECT。默认受限。
Pi
从命令抽出 public hosts → Guardian → exact lease → allow_domain；无 host 时 Nono 写 network.block，有 host 才进入 per-call supervised proxy。
P2记忆与严格模式
Codex
审批缓存、execpolicy prefix amendment、session Remember、strict_auto_review 连 echo hi 也审。
Pi
Engine 内置 exact one-shot grant；只有显式 amendment 才产生 turn/session capability。没有 command-prefix approval cache；人审模式不在了。

⑥ 若还要对齐

剩余差异 / 值得评估

  1. 补齐 Nono 明确 denial reason 的 typed runtime boundary，再交 Guardian 做一次 exact retry；不要解析 stderr 猜测。
  2. generic tool 的 host-admission 只覆盖 reviewer gate，实际 side effect 仍由宿主 owner 负责；若要更强隔离，应接入对应 native owner。
  3. 评估 per-call nono run 的固定成本与长生命周期 Tool Sandbox / nono wrap 的适用边界。

不值得做

  1. Guardian V2 async scorer
  2. permission_request hooks
  3. execpolicy 前缀记忆
  4. 把人审 popup 请回来——除非产品要「Ask for approval」
