# Auto Approval Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a functional `Auto` permission mode that sends only Default-mode approval prompts to a separate model reviewer, keeps deterministic blocks and sandbox boundaries final, and safely falls back to human approval.

**Architecture:** The existing Default evaluator remains the authoritative deterministic gate. New focused modules build injection-resistant review requests, call `pi-ai`, parse strict results, and maintain denial state; `register.ts` selects human or automatic review and continues to own one-call capability binding and sandbox execution revalidation.

**Tech Stack:** TypeScript 5.9, Vitest 4, `@earendil-works/pi-ai` 0.82.1, `@earendil-works/pi-coding-agent` 0.82.1, `@anthropic-ai/sandbox-runtime` 0.0.26.

## Global Constraints

- Automatic review never overrides `evaluateDefaultRequest(...).action === "block"`.
- Every approval remains bound to tool-call ID, tool, full input, cwd, config fingerprint, active mode, temporary network hosts, and temporary write roots.
- Reviewer calls have no tools, no prompt cache, no provider retry, a positive bounded timeout, and cancellation.
- Tool results, assistant prose, custom messages, and project instructions cannot establish user authorization.
- Reviewer failure falls back to the existing Yes/No UI only when dialog-capable UI exists; headless execution fails closed.
- Three consecutive denials pause Auto by default; `/auto` explicitly resets and resumes it.
- Different automatic reviews may run concurrently by tool-call ID; human dialogs remain serialized.
- The statusline displays only `Default` or `Auto`.
- Until Plan enforcement has its own approved spec, the functional mode cycle is `Default → Auto → Default`.
- Do not add an AlwaysApprove/YOLO path or any sandbox bypass.

```ts
  modelRegistry: Pick<ModelRegistry, "find" | "getApiKeyAndHeaders">;

export interface AutoReviewer {
  review(

    context: AutoReviewerContext,
    signal?: AbortSignal,
  ): Promise<AutoReviewResult>;
}

export type AutoReviewerFailureKind =
  | "unavailable"
  | "timeout"
  | "cancelled"
  | "provider"
  | "parse";

export class AutoReviewerFailure extends Error {
  constructor(
    readonly kind: AutoReviewerFailureKind,
    message: string,
    options?: ErrorOptions,
  ) {
    super(message, options);
    this.name = "AutoReviewerFailure";
  }
}
```

```ts
const model = context.reviewer
```
