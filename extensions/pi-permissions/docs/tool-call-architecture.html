Approve for me · 当前链路

对照 Pi vs Codex 差异 · 权限模式只剩 auto（状态栏「Approve for me」）和 yolo（「Full bypass」）。 人审 popup / default / plan 已退休。auto 下凡确定性策略判成 prompt 的调用，一律交给 Guardian 代用户裁决；批准只授权一次精确调用，真正副作用仍由拥有执行边界的 adapter 完成。

① 总览：判定和执行是两次独立调用

宿主 agent loop 先发 tool_call 事件（扩展可 block），通过后再调工具的 execute。 托管的 bash/write/edit 在 execute 入口直接进入 Engine； 其它宿主工具才在 tool_call 钩子做 host-admission。 Approve for me 把 admission、Guardian、精确一次性 grant 和 permission amendment 放进 ApproveForMeEngine，把实际 边界交给对应的 adapter。SRT adapter 通过统一的 execute({policy, program, cwd, env}) seam 负责 argv、child lifecycle 和 cleanup；进程级 coordinator 独占 SRT 的 mutable config， cleanup/restore 失败会 poison executor，后续请求 fail-closed。宿主 bash 默认 120 秒、file operation 默认 30 秒，所有 deadline 覆盖 initialize / wrap / child / cleanup。

② Phase A · Engine admission（谁能跑）

入口：register.ts 将每个受管工具的输入送入 ApproveForMeEngine。bash/write/edit 在各自 execute 入口完成 admission；其它宿主工具由 pi.on("tool_call") 进入 host-admission。Engine 的 blocked 结果会被 adapter 转成宿主拒绝，只有通过后才执行。

0 · 建立精确调用身份
tool + input + cwd + metadata + config/session 组成调用指纹； 旧 turn、旧 call id 或变更后的输入都不能复用授权。
激活activateConfig + turn snapshot
宿主用 PermissionSession 的 generation、turn lifecycle 和 barrier 保护激活；Engine 接收不可变 TurnSnapshot。 快照失效或不可用 → fail-closed。
短路snapshot.mode === "yolo"
yolo 由 Engine 直接给出 unrestricted lease，跳过 Guardian 和 sandbox；模式切换通过 host lifecycle/barrier 使新 turn 获得新快照。
确定性门evaluateRiskRequest
输入：工具名、payload、cwd、当前 config、受保护写路径。
risk-policy.ts 输出 allow | prompt | block， adapter 再投影为 Engine 的 AdmissionPlan；评估或快照失效 → 「permission context changed」，抛错 → fail-closed。
allow放行
LOW 或规则 allow。不铸造 grant；sandbox-owned 调用直接 使用基线 lease，host-admission 则只放行到宿主自己的工具执行。
block硬拒绝
私网、规则 deny、受保护路径、非法 git 网络、无法规范化的请求等。 不进 Guardian，不进 execute。
prompt送 Guardian
人审已退休，prompt 是 Approve for me 的唯一去向。Engine 传递 精确 action 或 capability request；paused / 缺调用 id → 直接拒绝。
generic tool 的 host-admission 会把静态 prompt 投影为唯一的 { kind: "external-tool", provider: "pi-host", name } capability。它覆盖 reviewer gate，不声称 SRT 已隔离该外部工具； bash/write/edit 才由 SRT adapter 拥有 OS enforcement。

确定性门内部（仍是 auto 链路的前置过滤器）

步骤 做什么 典型 HARD / REVIEW
normalizeToolCall 工具 → operation / 路径 / 命令段 / 网络目标 无法解析的 fetch URL → HARD
显式 permission amendment request_permissions 的 turn/session 请求 只经 Guardian 批准且成功确认后写入 capability world
git 约束 隐式网络要读 remote；突变要能授予 metadata 多命令 git、不安全 remote、init 目录检查失败 → block
resolveAdditionalWriteRoots bash 的 additional_permissions + git write roots 申请不成立 → block
matchRules config.rules：deny / ask / allow deny → block；ask → 至少 prompt
私网 isPublicNetworkHost localhost / RFC1918 / 链路本地 → block
classifyRisk 危险命令、网络可执行、替换/重定向、出站 CLI HARD 保持 HARD；出沙箱写 / 删 → REVIEW
admission projection static risk → AdmissionPlan 只表达待审请求；不直接扩大 base policy
Guardian 看到的 defaultRisk / defaultReason 来自这次 prompt 决策，只是证据，不是裁决。最终 outcome 由模型按 Codex 对齐策略产出。

③ Guardian 评审（Approve for me 本体）

Engine 的 runReview() → createPiGuardianAdapter → PiAutoReviewer.review。 生产路径注入的是 createSandboxedGuardianToolRuntime（SRT 全读、零写、零网）；adapter 只组装证据，Guardian 不能改变 capability lease。

1 · 登记评审
Engine 以调用 id 防止并发重复执行，并为在途 Guardian review 保存 AbortController，和 ctx.signal 合成 AbortSignal.any。Engine invalidate / turn close 会中止在途 review；PermissionSession 只负责 host lifecycle/barrier。
2 · 组装信封 buildAutoReviewRequest
untrustedAction（工具名 + 输入 + cwd）、裁剪后的 transcript、 permissionContext（sandbox 写根 / deny / 已允许与请求的域名 / 确定性 risk）、可选的 /approve override。
transcript 优先 message_end 累积，否则退回 input 事件；boundGuardianTranscript 限制 12k 字符。action JSON 超过 16k 直接失败。
3 · 模型 resolveGuardianModel
config.reviewer.provider/model 能找到且有可用 auth → configured。
否则回落到当前会话模型 active-fallback（UI 警告一次「preferred model unavailable」）。两边都没有 → unavailable，fail-closed。
4 · 会话租约 + 90s 截止
GuardianReviewSessionManager.open 按 cwd + configFingerprint + provider + model 复用 trunk，最多 8 轮 / 24k 字符历史。
系统提示 = Codex 策略模板 + tenant policy（默认 CODEX_GUARDIAN_DEFAULT_POLICY，可被 guardianPolicySource 替换，上限 16k）。
用户消息是一份 JSON：untrustedTranscript / untrustedAction / permissionContext / trustedDeveloperMessages / outputSchema。
单次 attempt（最多 3 次 · 指数退避 250ms→1s）
  1. complete()：Guardian 模型，cacheRetention: "none"， maxRetries: 0，reasoningEffort 来自 config（缺省 medium）。
  2. 若 stopReason === "toolUse"：并行跑只读工具 read / grep / find / ls / inspect（SRT 只读 policy，rg 必须是预先解析的绝对路径）。 inspect 固定为 {command:string} schema，参数和输出有上限； 外层固定 /bin/bash -c，由 SRT 只读/无网络 policy 与 30s host deadline 约束，临时 scratch 遵循 sandbox 默认值。 只允许 一轮 工具，第二次再 toolUse → provider 失败。
  3. 工具结果里只要有 isError，禁止 outcome=allow。
  4. 最终必须 stopReason === "stop"，正文解析为 JSON： outcome: allow | deny，可选 risk_level / user_authorization / rationale。低风险允许精简为 {"outcome":"allow"}。
  5. 解析失败或可重试的 5xx / 断连：未超 attempt 且未到 90s 则重试； 超时 → kind: "timeout"，对调用方仍是拒绝（没有人审兜底）。
approve
Engine 清零当前 turn 的连续拒绝计数，并保存绑定调用身份的 exact one-shot grant；随后 adapter 执行同一调用。普通 approval 不修改 base sandbox policy，也不产生持久 permission grant。
deny
记入 Engine 的 bounded denial notices（最多 10 条）。 连续 3 次 deny，或最近 50 次评审里 10 次 deny → 当前 turn 的 circuit open，通知并 ctx.abort()。
给模型的拒绝文案要求换更安全做法，禁止绕过。
error / timeout
一律 block 并 fail closed；review timeout / provider error 不会铸造 grant，且非 caller abort/stale 的非拒绝结果会清零 consecutive-denial breaker。cancelled 视为上下文已变。

Guardian 能碰什么

  • 固定只读工具：read / grep / find / ls / inspect
  • inspect 是固定 schema、参数/输出有上限的诊断 command surface；外层固定 /bin/bash -c，受 SRT 只读/无网络 policy 与 30s host deadline 约束，临时 scratch 遵循 sandbox 默认值
  • 工具跑在 Guardian 只读 sandbox（业务 allowWrite 为空；临时 scratch 遵循 SRT 默认）
  • 敏感错误串（Bearer / API key）打码

Guardian 不能做什么

  • 不能自己 mint grant 或改 sandbox
  • 不能批准「工具报错后仍 allow」
  • 不能覆盖策略里的显式 deny / critical

暂停怎么解开

  • 下一轮 agent_start 重置 auto 状态
  • Shift+Tab 切走再切回 auto
  • 暂停期间后续 prompt 直接拒绝，不再调用模型

④ Engine 授权（判定的唯一输出）

Engine 在 Guardian approve 后保存一条绑定当前 invocation 的 exact one-shot grant；字段在批准当下冻结，adapter 进入前按指纹核对并 consume。它是 Engine 内部状态，不是可供其它模块写入的独立 ledger。

字段 来源
callFingerprint session/config/ownership + tool + exact input + cwd + metadata + call id
requested Engine 规范化后的 capability requests
effective lease base sandbox policy ∪ 本次 exact request；host-admission 不伪造 SRT policy
turn/session amendment 只有显式 request_permissions 经 Guardian 批准、确认成功后才写入
LOW 的 allow 路径没有 grant，直接使用 base lease。普通 Guardian approval 只产生 invocation-scoped lease，不写回 base policy；一旦调用身份或 capability request 改变，verify 失败并 fail closed。只有 request_permissions 是明确的 turn/session amendment。

⑤ Phase B · wrapped execute（批准了什么被强制）

bash / write / edit 的 execute 都把 invocation 交给 Engine，再由 register.ts 的 concrete adapter 执行。 Guardian 只提供 decision；Engine 负责把它变成精确 lease，adapter 负责实际副作用和 enforcement。

门 1入口 abort
if (signal?.aborted) return abortedResult。堵住「钩子放行之后、execute 之前」被 Esc 的窗口。
activate同一套快照
Engine 检查 active TurnSnapshot 和 sandbox readiness。 快照丢失或 sandbox 不可用 → 抛错，不裸跑。
yolounrestricted lease
Engine 给出 unrestricted lease 后直接调用宿主 bash/write/edit。不进 Guardian、不进 SRT。
租约CapabilityLease
Engine 将 base policy 与本次 exact request 合并为不可变 lease； exact approved `.git` protected root 才能移除对应 grantable deny， broad root 和 `.agents`/`.codex`/权限配置等 hard deny 不会解锁； srtProcessCoordinator 是 process-global exclusive lease， 串行化 SRT config reload / child execution，不拥有审批状态。
门 2Engine authorize
verify(session/config/ownership/tool/input/cwd/metadata) → consume。 consume 在 adapter 进入之前发生；篡改 input、cwd、metadata 或重复 调用不能拿旧批准重试。普通 approval 仍是 invocation-scoped， 不改 base policy。
门 3sandbox 就绪
yolo → 由 Engine 明确给出 unrestricted lease；auto 下 sandbox disabled 或未 ready / 无 baseSandboxConfig → 抛错，附 SRT 不可用或上次失败原因。
concrete adapter按工具裁剪世界
write / edit：由 createSandboxedFileOperations 使用 lease.policy。
bash：由 createSandboxedBashOperations 使用 同一份 lease.policy；network hosts 进入本次 SRT policy 的 allowedDomains。
permission-amendment 的 acknowledgement 只在 Guardian 批准后执行， 成功才把 request 写入 turn/session capability world。
SRT executor
每次 sandbox-owned 执行将 backend-neutral policy 转换为 SRT denyRead / allowWrite / denyWrite 与 network 规则；denyRead 与 denyWrite 独立，不做 union。SRT wrapWithSandboxArgv 只在 coordinator lease 内调用，返回 argv/env 后由 adapter 以 shell:false spawn；stdout/stderr 有界，abort/timeout 杀 detached process group，随后 cleanup 并恢复 base config。Linux 含 glob 的 deny policy 确定性不可用，不静默放宽。 Git init 只接受 canonical system Git 的 typed plan，并以预创建的 .git、hard-deny hooks、exact config release 和空 template helper 运行；任一恢复/清理失败都会 poison 全局 executor。

⑥ 旁路：/approve、Shift+Tab、turn 生命周期

/approve精确重试一次被拒动作
仅 auto + 有 UI。从 Engine 的 bounded denial notices 倒序列表，用户选一条 → armRetry 生成 pending retry handle（精确 action fingerprint）。
然后 pi.sendMessage 注入 developer 前缀 「The user has manually approved a specific action that was previously Rejected.」，triggerTurn: true。
模型重发完全相同的工具调用时，Engine 将 override 放进 Guardian review context。仍然要过 Guardian，且只允许 这一次精确 retry；消费后 denial notice 和 handle 失效，critical / 显式 deny 仍不可 overlay。
Shift+Tabauto ↔ yolo
被 app.thinking.cycle 占用则只警告。
模式切换由 host 的 mutation queue 和 transition barrier 串行化； 当前 turn 继续使用已捕获的 snapshot；但 active turn 从 yolo 降到 auto 时立即 abort，避免继续沿用 unrestricted snapshot，新的 mode 在下一 turn 捕获。切换/branch/config context reset 会清掉 Engine 的旧 grants 和 capability world。
Turn 边界：agent_start 分配 turn、清 auto denial breaker、拍快照；agent_end / agent_settled 结束 turn 并清 turn 级 amendment。session amendment 跨普通 turn 保留，在 session/tree/config context reset 时清除。 没有生命周期事件时，直接打到工具钩子会自己开一个隐式 turn——一旦观察过 真实 lifecycle，这个后门就关掉。

⑧ 角色对照

确定性策略

risk-policy.ts + permissions/*

  • HARD 永远不进 Guardian
  • LOW 可以不惊动 LLM
  • 执行时再跑一遍，防 TOCTOU

Guardian

auto-reviewer.ts + policy 模板

  • 只裁决 prompt
  • 只读工具一轮
  • 失败 = 拒绝，没有人审回退

ApproveForMeEngine

集中拥有授权状态

  • admission → review → exact grant
  • 指纹绑定 tool+input+cwd+metadata+context
  • turn/session amendment 仅显式请求产生

SRT + adapters

把 lease 变成内核边界

  • policy 按调用派生，child argv 由统一 executor 运行
  • initialize / wrap / child / cleanup 共用 deadline
  • bash 120s / file 30s host deadline
  • 二进制缺失或超时 fail-closed
Guardian 默认 outcome 阈值（策略锁死，不进 config.json）
reviewer.timeoutMs / maxAttempts / maxConsecutiveDenials 写在 config 里会加载失败。

缺省：low/medium → allow（显式 deny 或明确注入除外）； high → 仅当 user_authorization ≥ medium 且范围收窄； critical → deny。
用户在看到具体风险后明确重批同一动作，可以把 authorization 提到 high，仍盖不住 critical 和策略 deny。

常量：评审 90s、最多 3 attempt、连续 3 deny 暂停、窗口 50 里 10 次 deny 暂停、策略文本 16k。
对照旧稿：那一版只画了 Phase B（execute + sandbox）。当前 Approve for me 的中心是 Phase A 的 Guardian 代批，Phase B 只负责把那次批准的边界强制到 SRT 上。人审 popup 已不在链路上。
