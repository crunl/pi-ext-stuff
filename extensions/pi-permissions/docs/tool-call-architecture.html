② Sandbox 在链路中的四个角色

1 · 并发协调者（Coordinator）

runShared / runExclusive 两档租约：

  • 普通文件操作 → 共享租约，可并行
  • 带网络豁免的调用 → 独占租约，强制排队
  • 会话关闭时 runExclusive(reset) 安全重置

2 · 权限边界的执行者

grant 里批准的 writeRoots / networkHosts 不是建议，是沙箱配置的硬边界：

  • 写权限逐调用裁剪进 filesystem.allowWrite
  • 网络域名并入 allowedDomains
  • 策略级 denyRead / denyWrite 永久生效

3 · 网络出口的过滤代理

网络提权必须走 Filtering Proxy：

  • 所有出站流量经本地代理端口转发
  • 仅放行 grant 批准的域名
  • 未批准域名的请求在代理层被拒——进程内代码无法绕过

4 · Fail-closed 的最后防线

沙箱不可用时：

  • 抛错阻断，绝不静默降级为裸执行
  • 与入口 abort 门、epoch 再验证共同构成三层纵深防御
  • 唯一例外是策略显式声明 sandbox off

③ 三种执行形态对照

yolo 快速路径 auto · 无网络豁免 auto · 带网络豁免
Abort 门 ✅ 经过 ✅ 经过 ✅ 经过
grant 授权消耗 ❌ 直接撤销遗留 grant ✅ verify + consume ✅ verify + consume
租约类型 — SHARED（可并发） EXCLUSIVE（独占）
文件系统 宿主全权 base 白名单 + 本次 writeRoots 同左
网络 无限制 默认策略域 仅 grant 域名，经过滤代理
sandbox 故障时 不适用（本就不进沙箱） fail-closed 抛错，调用被拒
关键不变量：任何一次有副作用的执行，要么在 yolo 下用户显式放弃保护，要么其副作用边界 ⊆ 该次 grant 批准的边界。
