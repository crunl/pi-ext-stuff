对照：Skip 侧在审什么（严苛在哪根轴上）

词法透明但后果更重的命令恰恰不经 review——严苛落在「可证明性」轴，不在「风险」轴。

cd src && lscd 折叠成功 → Skip
git add -A && git commit -m复合写 → Skip（SRT 罩住）
bash -c "ls | wc -l"体递归展开 → Skip
python3 scripts/build.py脚本内容政策 → Skip
git reset --hard · clean -fdx · truncate工作区内删除 → Skip（SRT 兜底）
npx create-vite · git push · curl静态 Skip，连接边界收口
sudo npm i -g pnpm静态 Skip，OS 层收口（setuid 未验证）
GIT_* / EDITOR 拆分本地比 codex 更严且更对（codex miss）

判断：不算过于严苛，但严苛在错误的轴上

层内规则全部落在 词法可证明性 轴（静态 argv == 运行 argv 吗），而不是 风险 轴（后果被 SRT 兜住了吗）。 16 条里 12 条后果完全被 SRT 罩住，review 只买到一次意图层读全文的机会。

git reset --hard · git clean -fdx · sudo npm i -g · python3 script.py

是否为「过度」取决于意图审值不值每条不透明命令一次 LLM 往返——这是产品定价问题。09-19 P0 原则 1 倾向认为 tier-4 的 12 条沙箱内命令可以被静态安置，而不只是被审。
