pi-safety tool call 链路

以 bash 为例（它是最丰富的一条），从宿主调用到返回结果的实际调用链。行号均已实测。

bash 根本不走 tool_call 钩子。 两个宿主入口是分开的：pi.on("tool_call")（register.ts:2299） 第一行就把 {bash, write, edit, request_permissions} 返回掉 （register.ts:2302，PI_OWNED_TOOL_NAMES）； bash 的真入口是 pi.registerTool({label:"bash"}) （register.ts:2025），门控全在 execute 自己内部。 钩子只管 host-first / delegated / foreign 三类工具。
